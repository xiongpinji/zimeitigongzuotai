# 阶段一范围：批量 AI 剪辑、合成与发布

用户于 2026-09-25 明确调整顺序：先确定并交付批量 AI 智能剪辑、直播切片、素材合成和四平台普通视频发布；挂车只保留按平台商品 ID 接入的扩展端口，具体接口、资格与真实商品挂载在用户后续研究后再规划。此决定取代早期“阶段一同时实现四平台挂车”的排期，但不把最终商品能力视为已交付。

## 阶段一必须打通的主链路

1. 导入多个已获授权直播录屏，自动生成转写、场景/音频线索和高光候选；候选含证据与源时间码，可批量审核和修改。
2. 将高光候选放入独立时间线，按脚本与语义从授权素材库匹配 B-roll、字幕、音频和画幅；生成多个有实质不同叙事的可编辑版本，批量渲染并质检。
3. 为每个目标账号选定**具体视频版本**、标题、封面和发布时间，形成 `视频版本 × 平台账号` 发布矩阵。同平台多账号不能共用登录状态；同平台多账号若选了相同视频，应显式提示重复风险并允许更换版本。
4. 任务队列按账号互斥、跨账号并行且受平台预算约束；提交状态不明时先查询远端，避免重复发布。完成后保留作品 ID、链接/状态及失败原因。
5. Agent 经类型化 Skills 可执行上述生产链路；发布仅在预先授权的账号与时间范围内自动提交，异常停在人工可接管状态。

阶段一验收为 [R1–R5 与 R6-P](roadmap-and-acceptance.md)。`R6-C` 商品挂载不在阶段一实施或验收范围内。媒体质量按[高光与混剪协议](media-evaluation-protocol.md)评估，普通发布按四平台账号分别记录最终状态。没有真实账号时只能完成模拟/本地验收，不能宣称四平台已真实发布通过。

## 预留商品挂载契约，不实施挂车

每个发布任务可携带可选 `CommerceRequest`：`platform`、`accountId`、`kind`、`platformProductId`、`required`。商品 ID 是该平台自己的标识，不用通用 URL 代替。未来平台插件提供 `probeCapability → prepareAttachment → applyAttachment → verifyAttachment` 四步；账号权限、商品存在性、平台处理状态分别检查。

阶段一的四个平台商品插件均报告 `not_implemented`。若任务要求挂车（`required=true`），预检返回 `COMMERCE_NOT_CONFIGURED` 并阻止提交；`required=false` 仍进入 `needs_user_action`，只有用户显式移除商品请求并另建普通任务才可继续，绝不暗中降级成不带货视频。普通视频任务（无 `CommerceRequest`）不依赖商品能力，可独立排队和验收。后续用户研究确定各平台商品类型、发布接口与账号资格后，再增加实现和真实商品入口核验。

当前不能假定四个平台都支持“发布时传一个商品 ID 即自动挂载”。已有公开能力和待验证事项留在[平台能力准入门槛](platform-capability-gates.md)作为未来研究记录，不作为阶段一启动门槛。
