# Goal

在用户确认方案与本项目百炼 Credits 风险预算后，交付可安装、可验证的 Windows 本地自媒体工作台阶段一：四平台同平台多账号管理、独立视频剪辑台、批量直播高光、授权素材智能合成、可审计 Agent 自动生产及可恢复的批量**普通视频**发布。完成依据是 [R1–R5 与 R6-P](../roadmap-and-acceptance.md)，另完成商品请求拒绝与扩展端口；R6-C 商品挂载另立计划，不能用本计划完成状态代替。

# Decisions and assumptions

- **待用户确认的方案**：以 [Lingji Cut](https://github.com/yoqu/lingji-cut) 固定版本作桌面/时间线基座；Easel Skills 选择性借鉴；HotClip 作为隔离高光进程/CLI/MCP 候选，受 AGPL 分发审查门槛约束；OpenCut-AI 的 CLIP 索引路线用于素材匹配验证；social-auto-upload 只作平台适配器参考或补位。按 [组件组合图](../integration-map.md) 接入，不从零重建所有子系统。
- 四平台并列：抖音、快手、微信视频号、小红书。优先打通 `录屏 → 高光 → 素材匹配 → 多叙事时间线 → 渲染 → 视频版本 × 账号任务矩阵 → 普通发布 → 最终状态`。
- 阶段一的 `CommerceRequest` 只是契约：四平台商品插件返回 `not_implemented`；请求商品时阻止发布或等待用户显式移除请求。用户后续研究各平台商品类型、商品 ID、账号资格和可用接口后才启动 R6-C。
- “原创”仅指授权清楚、有实质性新表达、可追溯的作品生产；平台原创标签、推荐量和流量不在可保证范围内。
- **启动门槛**：用户确认本方案及本项目实际百炼 Credits 风险预算前，只有方案文档、Git 和只读环境检查；不运行写代码 Agent、付费模型、真实账号操作或发布。

# Constraints and guardrails

- Codex 是总指挥、集成和独立验收人。实现只用 `claude-bailian=qwen3.8-max` 与 `opencode-bailian=bailian-token-plan-personal/deepseek-v4.1-flash`，审查只用 `qwen-code-review=glm-5.3` 且只读；不自动替换或增加路由。至多两个实现任务并行，必须独立工作树或可证明互不重叠的文件范围；共享契约和集成串行。
- 每个 Agent Orchestrator job 绑定本清单一个条目、固定输入 SHA/允许文件、测试和退出证据；禁止执行 Agent 再派子 Agent、自行提交/推送/部署/改凭证。Codex 审查完整 diff、独立复测并记录 verdict 后才解除下游依赖。
- 测试按源码可见、本机自动化、真实授权账号、平台最终状态四层分别记录。一个层级不能替代下一层；无真号时 R1/R6-P 对应平台不能宣称通过。发布会话与素材、录屏不入 Git 或模型提示。
- 单账号互斥、账号之间受平台/设备预算控制；限流退避，验证码或权限异常停机；未知提交先查远端再决定，不盲重发。Agent 只能通过类型化任务 API 发布，默认停在草稿，活动预授权明确账号、时间窗和上限才允许自动提交。
- 第三方版本、来源、许可证、NOTICE、依赖、安全与 Windows 运行结果逐项记录。AGPL 组件分发方式未经审查不能把 HotClip 源码混入宽松许可模块；不以平台风险规避或伪原创作为目标。

- [ ] P0-2：定义 `Recording`、`Highlight`、`Asset`、`CompositionPlan`、`VideoVariant`、`Account`、`PublishJob`、`CommerceRequest` 的版本化契约和迁移测试；明确单一项目模型与进程通信边界。
- [ ] P0-3：完成组件来源/许可证清单与 HotClip 隔离进程试验；在本机验证 CLI 或 MCP 的输入输出、超时、取消、资源占用和合法分发方式，无法通过则保留接口替换实现。
- [ ] P1-1：实现四平台同平台多账号的内部 UUID、隔离加密会话引用、登录/过期探针/重登/删除和审计，验证一账号过期不影响同平台另一账号。
- [ ] P1-2：实现持久发布任务矩阵、单账号锁、平台/设备预算、计划时间、取消、退避、重启恢复、未知提交远端核对及最终远端 ID/状态。
- [ ] P1-3：在 P1-1/P1-2 契约上接抖音、快手普通视频适配器；按平台各做模拟、授权账号与最终状态分层证据，账号或路径不足时记录未通过。
- [ ] P1-4：在同一契约上接视频号、小红书普通视频适配器；同样分层验收，并保留需要人工接管的真实状态，不能把人工操作算自动通过。
- [ ] P2-1：批量导入多个录屏，生成转写、场景/音频和可用互动证据；输出带源哈希、时间码和解释的高光候选，支持中断恢复及低高光负样本。
- [ ] P2-2：把候选带入独立时间线，完成边界调整、竖屏重构、字幕/封面、批量导出与单片失败恢复；按 R3 事先标注样本和双人盲审记录结果。
- [ ] P3-1：建立授权素材库、许可与使用范围过滤、语义索引/检索、B-roll 推荐理由及来源追溯；无权素材不得被自动选中。
- [ ] P3-2：生成至少三版实质不同叙事的 `CompositionPlan`，回写同一可编辑时间线、批量渲染，并做文本/镜头/音频相似度复核及 R4 对照盲审。
- [ ] P4-1：将九项类型化生产工具映射到本地任务 API，按需组合 Easel Skills 和 HotClip MCP；完成录屏到渲染的可暂停、可审计自动闭环。
- [ ] P4-2：在预授权活动内串接普通视频预检、排队、平台最终状态核验；无授权、过期会话、无权素材或不确定提交必须停机且可人工接管。
- [ ] P5-1：为平台插件保留 `probeCapability → prepareAttachment → applyAttachment → verifyAttachment` 商品接口；四平台均返回 `not_implemented`，有 `CommerceRequest` 的任务不能静默转成普通发布。
- [ ] P6-1：模拟 100 账号/1000 任务和 8 个可配置 worker 的队列目标，做进程崩溃、限流、超时、重启及未知提交故障注入；记录真实平台速率而不把模拟并发当真号许可。
- [ ] P6-2：完成 Windows 安装/迁移/备份、凭证与素材保护、依赖与许可证审查；对 R1–R5、R6-P 逐项归档本地和四平台真实普通发布证据，未满足项明示未通过。

# Validation strategy

开发后每项先写有意义的失败测试再实现；Codex 审查变更边界并独立跑聚焦测试和相关构建。编辑器验收含工程重开、时间线人工修改、预览/导出一致；媒体按[高光与混剪协议](../media-evaluation-protocol.md)先标注再运行、保留失败样本；队列覆盖并发冲突、重启、取消、限流、超时和未知提交。平台发布先模拟，再对用户授权账号按平台记录提交及最终远端状态，未经验证的平台维持未通过。最后独立运行长时本地负载、Windows 安装和许可证审查；Qwen/GLM 只读复审高风险 diff，Codex 根据实际证据验收。

# Completion criteria

R1–R5、R6-P 的目标场景有可复现证据并逐项关闭，四平台真实普通发布及账号保持有实际结果；无法取得平台路径或账号时保留未通过而不做虚假完成声明。所有接受的 Agent 改动经过 Codex 完整 diff/测试复核和记录，Windows 发行与第三方许可可交付。商品扩展端口及拒绝测试完成即可结束本阶段，不把 R6-C 计入本阶段完成；后续商品实施需新的确认和验收计划。
