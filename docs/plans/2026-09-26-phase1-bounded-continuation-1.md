# Goal

续建已确认的阶段一主线，先消除账号会话与发布队列的高风险断层，再接普通发布、媒体和 Agent。承接 [主方案](2026-09-25-phase1-core.md) 与 [当前证据](../validation/phase1-progress-2026-09-26.md)；本计划是第一批细分清单，不把旧清单的局部代码当作完整验收。

# Decisions and assumptions

- 用户在 2026-09-26 对“保持原三路、拆分新有界清单继续”的推荐选项回复“确认”。按整个阶段一主线执行；预算无百炼 Credits 硬上限，但不改变角色或放宽单项尝试上限。
- `claude-bailian/qwen3.8-max` 主要实现，`opencode-bailian/bailian-token-plan-personal/deepseek-v4.1-flash` 并行实现，`qwen-code-review/glm-5.3` 只读审查；Codex 负责分解、集成及独立复核。
- 输入主库基线 `5fb76eb`。任何在途隔离工作树仅作候选素材，必须按文件清单、当前 SHA、测试与审查重新确认后才能合入。
- 商品挂载仍只保留端口及商品请求拒绝。没有用户授权账号和平台最终状态证据时，绝不声明真实发布成功；不保证平台“原创”判定。

# Constraints and guardrails

- 至多两个实现任务并行；共享契约与集成串行。每项独立工作树、精确允许文件、禁止子 Agent、提交、推送、部署、依赖安装、凭证变更及破坏性清理。GLM 审查只读。
- 先写有意义的失败测试，再实现。Codex 审查完整 diff 与高风险代码，独立运行聚焦测试及类型检查，并将真实账号、平台最终状态与离线测试分层记录。
- 任何明文 Playwright storageState 仅在独立临时目录中短时存在，失败/取消也须清理；账号 UUID 和加密会话引用不得暴露明文路径。未知提交先远端核对，旧执行器迟到时不得释放账号互斥或覆盖后续决议。

# Checklist

- [ ] A1：为 `AccountVault` 增加有界的登录临时会话事务：新账号与续登都支持平台写入 storageState，成功后验证并加密持久化；失败、异常和取消保持旧会话，清理独立明文目录。仅改账号仓、聚焦测试和验证文档，不接 IPC。
- [ ] Q1：GLM 只读审查 `DurablePublishQueue` 的跨实例租约、在途上传与迟到结果竞态，给出失败时间线、可运行负例及最小修复文件清单；不改代码、不把模拟并发当平台许可。
- [ ] Q2：依据 Q1 经 Codex 审定的契约，修复发布队列同账号在途互斥与旧尝试结果覆盖；覆盖过期租约、重开实例、未知提交、手动决议、取消及崩溃恢复，未证明的跨进程保证须明确留红。
- [ ] A2：在 A1 验收后建立账号服务与 Electron IPC 安全桥，同步 preload 和 Renderer 类型；四平台登录、列出、探针、删除从 UUID/加密会话路径走通，旧数据显式迁移，单账号失效不影响同平台其他账号。旧发布路径在替换前不得宣称已切换。
- [ ] M1：在现有 sidecar 上建立来源权利与授权素材筛选的最小纯函数边界，拒绝无权素材并保留来源追溯；不推断自由文本许可、不声称真实 CLIP 索引已完成。
- [ ] P1：在 A2、Q2、M1 的本地门槛通过后，分项串接预检、受信任活动授权、持久队列与平台最终状态查询；先模拟后授权账号，商品请求保持阻止，未取得远端最终状态一律保持未知。

# Validation strategy

A1/Q2/M1 做 RED→GREEN→复测；Q1 给出可复现的源码时间线和测试断言，Codex 复核后才启动 Q2。账号事务需要合成 storageState、加密不可用、失败与清理失败测试；队列覆盖两个实例和迟到 Promise；IPC 涉及 main/preload/Renderer 三件套。每项通过后选择性合入主库、推送并更新证据页。后续高光、混剪、商品端口、发行和四平台真实验收仍按主方案继续细分，不由本批局部测试关闭。

# Completion criteria

六项均有独立 review verdict、当前 SHA 的聚焦验证和准确文档；账号明文路径不进入持久化或日志，队列竞态不被虚假标记为安全，发布链路只在最终状态有证据时记成功。未完成项或平台资格缺失继续在总计划保持未通过。
