# 阶段一 Q2 队列续建：失败读取与跨进程写入门槛

# Goal

交付可审计的同进程队列修复，并通过 Windows 双进程故障注入确立跨进程
存储所有权门槛；此前不把队列接到自动发布入口。

# Decisions and assumptions

本计划续接 [阶段一主线](2026-09-25-phase1-core.md) 的 P1-2 和
[首批有界清单](2026-09-26-phase1-bounded-continuation-1.md) 的 Q2。
主库输入为 `20937a5`；隔离工作树 `zimeitijuzhen-ao-q2-finalize` 从主库创建，
只复制前一轮队列候选的 `durable-queue.ts` 与测试文件。旧工作树中白名单外的
`.tmp-dq-harness.mjs` 没有复制，也不得进入主库。

前一轮 DeepSeek 候选的 38 项队列测试和主库依赖环境下的 `tsc --noEmit` 曾由
Codex 独立验证通过；GLM 只读审查未发现**同进程** P0/P1 问题。随后 Qwen
补了三个定向测试，却因在工作树根目录创建白名单外临时脚本被 AO 终止。
当前隔离候选的官方 Vitest 实测为 **40/41**：失败项是「storePath 为目录时，
构造必须抛固定消息的 `DurableQueueError('store_read_failed')`」，源码尚直接
抛出 `EISDIR`。此 RED 必须先修，不能把 40/41 写成通过。

# Constraints and guardrails

- 仅使用用户确认的 Qwen 主实现、DeepSeek 并行实现和 GLM 只读审查三条路由；
  Codex 分解、独立测试与选择性合入。新任务有独立工作树、精确白名单、时限；
  执行代理不得派生子代理、改凭证、提交、推送或部署。
- 已存在的 40 项绿色队列测试不得削弱。提交未知时只进远端核对或人工处理，
  不自动重发；未过期的 `uploading` 租约不因打开新实例被清掉，迟到结果不得
  覆盖人工决议，同账号在途任务互斥。
- 指纹比对、进程内活动注册表不是跨 OS 进程原子 CAS。两个独立进程可能同时
  读到同一旧字节并先后 `rename`，造成丢失更新。没有 Windows 双进程负例、
  产品单实例/存储所有权门槛或等效 OS 锁前，不把队列接到自动发布入口。
- 所有验证先用合成任务；四平台真实发布权限、频率、远端作品 ID 和最终状态
  另按平台验收。商品请求保持阻止，不推断视频“原创”或平台许可。

  故障注入和崩溃恢复的最小验收方案；不修改代码。
- [ ] Q2-R3：按 R2 经 Codex 审定的单一方案实现跨进程门槛与 Windows

  P1 接线；如果只保证 Electron 产品单实例，必须显式限制所有队列写入入口，
  不把通用队列 API 宣称为任意进程安全。

# Validation strategy

R1 保留并独立重跑 41 项队列测试，重点检查不可读存储、迟到结果、未过期
上传租约及失败后重开；`tsc --noEmit` 与精确文件差异检查均须通过。R2 只读审查
给出可证伪的跨进程时间线与门槛，不把设计当测试。R3 用 Windows 上两个独立
进程同时操作同一 store，覆盖崩溃、重启、同账号租约、异常退出和恢复，核验
磁盘任务无丢失、无盲重发。Codex 审查所有结果，真实平台状态另行验收。

# Completion criteria

R1 的完成仅意味着离线**同进程**候选通过，不等于 P1-2 或 R6-P 完成。
R2 的评审不能替代 R3 的实测。最终仍须逐平台授权账号验证提交与远端最终
状态；未获得证据时保持未通过，不能靠本地任务状态推断发布成功。
