# 分阶段交付与验收矩阵（待确认）

本路线按可演示的纵向能力交付，不把依赖仓库的宣传语当作成品。每阶段均提交代码、测试、样例工程、失败路径证据与版本说明；Codex 在 Agent 审查后复查 diff 和运行测试。尚未取得真实账号、商品挂载资格或平台最终状态时，相应项只能标记“待真实验收”。

| 阶段 | 交付物与退出门槛 | 可并行边界 |
| --- | --- | --- |
| M0 基座和契约 | 导入固定 SHA 的 Lingji Cut，保留许可证/历史来源；Windows 可启动、示例工程可编辑/渲染；定稿 `Account`、`Recording`、`CompositionPlan`、`PublishJob` 与适配器接口，建测试夹具和 CI。 | 桌面基座与数据契约由不同工作树实现，集成时串行。 |
| M1 多账号与可恢复发布 | 四平台同平台多账号增删/登录/会话探针；账号隔离、过期提示；一视频多账号、一账号多视频的任务矩阵；持久队列、单账号锁、取消、重启恢复、远端状态核对。 | 每个平台适配器可分工，队列和共享类型由主实现单独负责。 |
| M2 直播切片 | 多个录屏批量导入，转写/视觉/音频证据生成候选、人工校正边界、竖屏重构和批量导出；中断可恢复。HotClip 候选在许可和 CLI 契约验证后接入。 | 与 M1 平台适配器分离。 |
| M3 语义素材与多版本 | 有授权元数据的素材库、索引与检索；高光与 B-roll 自动匹配；至少三种有不同脚本/叙事结构的可编辑版本；重复提醒和来源追溯。 | 索引进程与编辑器 UI 可拆分，最终渲染集成串行。 |
| M4 Agent/Skills | 九项类型化工具，录屏到渲染与质检自动链；预授权活动内可自动排队、发布并核验；异常进入可见待处理状态，审计完整。 | Skills 契约可与适配器实现并行，端到端串行。 |
| M5 带货能力 | 账号级商品权限探测、商品目录/ID 映射、平台化挂载、预检和发布后确认；四平台各有明确支持/人工/不可用状态，带货失败绝不静默降级。 | 各平台带货适配器可隔离开发，真实账号验收需要相应资质。 |
| M6 负载与交付 | 故障注入、长时间队列运行、Windows 安装包、迁移/备份、依赖与许可清单；四平台真实账号试点、商品路径和最终平台结果记录。 | 压测/安全/许可审查可并行，发布前汇总。 |

## 产品验收（六项必须逐项关闭）

| 编号 | 独立可核实的验收场景 | 不接受的替代证据 |
| --- | --- | --- |
| R1 多账号 | 每个平台至少两组**用户授权**账号，重启后独立保持；账号 A 过期不影响 B；同平台批量选择与状态可见。先在模拟平台跑 100 个保存账号与会话状态测试，真实账号上限以平台实际政策/权限为准。 | 只保存多个昵称、共用 Cookie、README 支持声明。 |
| R2 剪辑台 | 打开样例工程，完成多轨分割/字幕/封面/画幅/撤销，保存重开后时间线一致，预览和导出比对通过。 | 只有 FFmpeg 命令或外部独立应用跳转。 |
| R3 高光 | 至少一份 2 小时录屏及另一份录屏批量处理；候选带时间码与证据，选出 10 段以上可独立观看的切片，人工可调整并批量导出；中断恢复无重复产物。质量由人工评分样本记录。 | 单次示例剪 1 段，或仅随机等时长切割。 |
| R4 智能混剪 | 对同一授权录屏及授权素材库，生成至少 3 个不同叙事结构的时间线，能追溯每段来源和授权；内部查重报告和人工审看确认实质差异。平台原创认定/推荐量不承诺，由真实发布后的平台反馈单独记录。 | 只换封面、BGM、滤镜、转场或扰乱顺序。 |
| R5 全流程 Agent | 在预授权活动下，从导入录屏到高光、素材匹配、时间线、渲染、预检、排队、发布核验可自动完成；故意设置无权素材、过期登录、无带货资格，流程必须停止并给出可恢复原因。 | Agent 只输出文字建议，或绕过授权直接操作浏览器。 |
| R6 并发和带货 | 模拟 100 账号/1000 任务队列、8 个可配置并行发布 worker：同账号互斥、任务不丢不重、重启/超时/未知提交能恢复或待核对。四平台各用有资格账号验证普通发布与按账号选择商品的路径，并检查远端商品入口和最终发布状态。真实吞吐以平台限额和账号资格测得，不承诺无限并发。 | 仅 UI 多选、线程数配置、上传接口返回成功、无资格账号的商品选项截图。 |

模拟性能值是**本机调度器容量目标**，并非允许向平台同时发送 8 次或承诺 100 个真实账号可发布。真实发帖速率、账号资格和并发预算由适配器探针、平台规则及试点结果约束。对每个平台记录队列等待、上传/处理耗时、最终成功率、限流与封禁信号；出现风险信号自动降并发或停派。

## 开发顺序与用户决策点

1. 本方案确认后，先执行 M0；M1 的任务引擎与 M2 的高光接口可并行，不能让两个 Agent 同改发布核心或项目模型。
2. M0 验证 HotClip 以独立 AGPL 组件交付的许可证义务和包装方式。若无法满足，保留接口，改用自实现/宽松许可组件，不能悄悄混入源码。
3. M1 前确定真实账号测试范围。M5 前由各平台有资格账号确认商品类型、挂载权限及可用接口；未提供账号时可以完成模拟测试和实现，但 R1/R6 真实验收保持未通过。
   平台与商品类型的公开证据及待核查项目见[能力准入门槛](platform-capability-gates.md)。
4. 发布动作需要明确预授权策略；默认仅生成草稿和预检。用户开启特定活动自动发布后，Agent 才可按限定范围提交。

方案待确认的核心决策：以灵剪作为基座、Easel 作为技能来源；本地桌面优先；HotClip 作为独立组件候选并设 AGPL 门槛；四平台带货按真实资格逐一接入，不保证任意商品 URL 通用；“原创”采用实质表达与追溯标准，不保证平台标签。若任何一项不符合预期，应在开发前调整本文件和架构文档。
