# 分阶段交付与验收矩阵（待确认）

本路线按可演示的纵向能力交付，不把依赖仓库的宣传语当作成品。阶段一范围是 R1–R5 与 R6-P（普通发布队列）；R6-C（商品挂载）只留契约，待用户完成各平台商品接口和资格研究后另立实施计划。每阶段提交代码、测试、样例工程、失败路径证据与版本说明；Codex 在 Agent 审查后复查 diff 和运行测试。尚未取得真实账号或平台最终状态时，相应项只能标记“待真实验收”。

| 阶段 | 交付物与退出门槛 | 可并行边界 |
| --- | --- | --- |
| M0 基座和契约 | 导入固定 SHA 的 Lingji Cut，保留许可证/历史来源；Windows 可启动、示例工程可编辑/渲染；定稿 `Account`、`Recording`、`CompositionPlan`、`PublishJob` 与适配器接口，建测试夹具和 CI。 | 桌面基座与数据契约由不同工作树实现，集成时串行。 |
| M1 多账号与可恢复发布 | 四平台同平台多账号增删/登录/会话探针；账号隔离、过期提示；一视频多账号、一账号多视频的任务矩阵；持久队列、单账号锁、取消、重启恢复、远端状态核对。 | 每个平台适配器可分工，队列和共享类型由主实现单独负责。 |
| M2 直播切片 | 多个录屏批量导入，转写/视觉/音频证据生成候选、人工校正边界、竖屏重构和批量导出；中断可恢复。HotClip 候选在许可和 CLI 契约验证后接入。 | 与 M1 平台适配器分离。 |

## 阶段一产品验收（R1–R5、R6-P 逐项关闭）

| 编号 | 独立可核实的验收场景 | 不接受的替代证据 |
| --- | --- | --- |
| R1 多账号 | 每个平台至少两组**用户授权**账号，重启后独立保持；账号 A 过期不影响 B；同平台批量选择与状态可见。先在模拟平台跑 100 个保存账号与会话状态测试，真实账号上限以平台实际政策/权限为准。 | 只保存多个昵称、共用 Cookie、README 支持声明。 |
| R2 剪辑台 | 打开样例工程，完成多轨分割/字幕/封面/画幅/撤销，保存重开后时间线一致，预览和导出比对通过。 | 只有 FFmpeg 命令或外部独立应用跳转。 |
| R3 高光 | 对事先标出至少 10 个高价值事件的 2 小时录屏、另一份不同录屏及低高光负对照批量处理；候选带时间码与证据，高信号样本 Top 10 至少 8 段经双人盲审可用，标注事件覆盖率至少 70%；人工可调整并批量导出，中断恢复无重复产物。详见[验收协议](media-evaluation-protocol.md)。 | 单次示例剪 1 段、随机等时长切割，或为凑数量把低价值片段当高光。 |
| R4 智能混剪 | 对同一授权录屏及授权素材库，生成至少 3 个不同叙事结构的时间线，能追溯每段来源和授权；双人盲审能说出每版独立信息价值，故意仅换封面/BGM或随机乱序的对照版本应被拒绝。平台原创认定/推荐量不承诺，由真实发布后的平台反馈单独记录。详见[验收协议](media-evaluation-protocol.md)。 | 只换封面、BGM、滤镜、转场或扰乱顺序。 |
| R5 全流程 Agent | 在预授权活动下，从导入录屏到高光、素材匹配、时间线、渲染、预检、排队、**普通视频**发布核验可自动完成；故意设置无权素材、过期登录、未配置的商品请求，流程必须停止并给出可恢复原因。 | Agent 只输出文字建议，或绕过授权直接操作浏览器。 |
| R6-P 批量普通发布 | 模拟 100 账号/1000 任务队列、8 个可配置并行 worker：同账号互斥、任务不丢不重、重启/超时/未知提交能恢复或待核对。四平台分别用授权账号验证普通视频发布、远端作品 ID 和最终状态；真实吞吐以平台限额和账号资格测得，不承诺无限并发。若某平台只能人工接管，就如实记录该平台未通过自动发布验收。 | 仅 UI 多选、线程数配置、上传接口返回成功、人工发布记录冒充自动发布。 |

模拟性能值是**本机调度器容量目标**，并非允许向平台同时发送 8 次或承诺 100 个真实账号可发布。真实发帖速率、账号资格和并发预算由适配器探针、平台规则及试点结果约束。对每个平台记录队列等待、上传/处理耗时、最终成功率、限流与风控信号；出现风险信号自动降并发或停派。四平台自动发布是验收目标，不是当前已证明的能力；平台限制或账号权限不足时单列阻碍，不能以模拟结果关闭该平台项。

## 后续商品验收（R6-C，不计阶段一完成）

用户研究确认各平台商品类型、账号资格和可用接口后，再按平台/账号/商品 ID 做 `probeCapability → prepareAttachment → applyAttachment → verifyAttachment`。每个平台分别证明有资格账号可选择商品、提交、查询最终状态，且作品页面显示正确商品入口；不支持自动化的平台必须明确为未完成或人工路径。接口占位、上传成功和商品选择页截图均不能关闭 R6-C。

## 开发顺序与用户决策点

1. 本方案确认后，先执行 M0；M1 的任务引擎与 M2 的高光接口可并行，不能让两个 Agent 同改发布核心或项目模型。
2. M0 验证 HotClip 以独立 AGPL 组件交付的许可证义务和包装方式。若无法满足，保留接口，改用自实现/宽松许可组件，不能悄悄混入源码。
3. M1 前确定真实账号普通发布试点范围；未提供账号时可以完成本地/模拟测试，但 R1 与 R6-P 的真实验收保持未通过。商品资格研究属于后续 R6-C，不阻塞阶段一普通发布。平台公开资料和待核查问题见[能力准入门槛](platform-capability-gates.md)。
4. 发布动作需要明确预授权策略；默认仅生成草稿和预检。用户开启特定活动自动发布后，Agent 才可按限定范围提交。

方案待确认的核心决策：以灵剪作为基座，按需组合 Easel Skills、HotClip CLI/MCP 与 OpenCut-AI 语义检索路线；本地桌面优先；HotClip 设 AGPL 门槛；阶段一完成批量 AI 剪辑、合成与普通发布，商品仅留扩展端口；“原创”采用实质表达与追溯标准，不保证平台标签。若任何一项不符合预期，应在开发前调整本文件和架构文档。
