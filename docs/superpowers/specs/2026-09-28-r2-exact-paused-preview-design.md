# R2 暂停帧与导出一致：源码阶段设计

阶段一方案已获确认；本设计只处理独立剪辑台的暂停、拖动和逐帧预览。用户当前要求先做源码测试，暂不打包。现有 [R2 呈现帧诊断](../../validation/r2-presented-frame-diagnosis-2026-09-28.md)表明，预览原生 `<video>` 的实际 `mediaTime` 会偏离 `OffthreadVideo` 导出选帧。[静帧探针](../../validation/r2-renderstill-feasibility-2026-09-28.md)在 15/30 fps 合成源、裁切入点和双轨画面上，以同一 Remotion composition 的 `renderStill()` 将逐帧 SSIM 提高至 0.984 以上；复用浏览器单帧约 0.55–0.72 秒。当前 UI 严格验收仍未通过。

## 方案选择

1. **选用导出路径的静帧覆盖暂停画面。** 播放中仍用 Remotion Player 保持流畅和声音；暂停/拖动时，在 Player 上层显示目标时间线帧的 `renderStill()` PNG。只有返回帧与当前工程版本、当前帧完全一致时才能显示。准备中显式提示，错误时标为“精确预览不可用”，不能把旧帧或原生视频伪装成精确帧。
2. 给原生 `<video>` 加固定 seek 偏移虽然开销低，但 15/30 fps 已出现不同偏差，可变帧率更不能推导统一偏移。
3. 改导出为原生 `<video>` 可让两端表面一致，却会降低既有准确取帧导出的保证，不采用。

## 数据流和边界

渲染进程发送工程时间线、SRT、项目目录建立当前预览会话；主进程重用现有导出素材 materialize、卡片编译和 Remotion composition 逻辑，按版本缓存一份 serve URL 与无头浏览器。暂停时渲染进程只请求会话中的目标帧，主进程返回 PNG bytes 和帧号，不返回临时文件路径。新版本或新帧到来时旧异步结果失效，连续拖动只处理最新请求；播放恢复立即移除静帧覆盖。关闭项目或窗口时释放浏览器及临时目录。预览缓存不得与导出共用可变工作目录或覆盖正在使用的 bundle。

素材绝对路径、卡片相对路径与字幕必须与导出输入一致。素材缺失、编译错误、渲染失败应形成可见错误，不静默显示不匹配帧。当前项目和素材仅在本机处理，不写入 Git、编排提示或持久日志。`renderStill()` 的约 0.6 秒仅是本机探针值；UI 应有短暂准备态并避免每个 pointer move 都新建 bundle/浏览器。

## 源码阶段验收

- 先用失败测试覆盖帧/工程版本失效、播放取消、重复帧缓存、素材变化与渲染失败；再接主进程及 UI。
- 15 和 30 fps 隔离工程在连续 42→43→90→42 帧拖动后，**实际桌面 UI 截图**与导出对应帧 SSIM 均不低于 0.92；记录等待精确帧的耗时及页面异常。
- 重开工程、改动时间线、字幕/画面叠层及可变帧率样本分别复测。默认 GPU 运行单列结果，不将 `--disable-gpu` 证据等同于默认路径。
- 类型检查、相关 Vitest 与 Electron 源码构建通过。打包态和真实录屏仍需在用户恢复打包/提供授权材料后另行验收，本阶段不得宣称通过。
