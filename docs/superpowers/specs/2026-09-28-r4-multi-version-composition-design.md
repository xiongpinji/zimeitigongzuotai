# R4 多叙事混剪：合成计划与可编辑时间线设计

状态：阶段一方案已由用户确认；本文件把 P3-2 的数据与执行边界落到当前 Lingji 工程。当前用户要求先做源码和离线测试，不打包、不连接真实账号、不发布。

## 方案选择

1. 把受众、论点和 B-roll 用途塞进现有 `narrativeSummary` 字符串：兼容性最好，但机器无法核验字段，审片与来源追踪会丢失结构。放弃。
2. 每次生成覆盖项目唯一 `timeline`：实现快，但第二版会覆盖第一版，不能同时保留三份可编辑时间线。放弃。
3. **选用结构化的计划扩展和独立版本工程**：保留现有 `CompositionPlanV1` 的来源片段与发布时间码契约，给新生成计划增加可验证的编辑意图；每版写入当前项目下的独立 Lingji 子工程，并在计划里保存该工程引用。旧版计划仍可读取，但只有具备完整编辑意图的计划可进入 R4 自动合成。发布预检继续以原有计划和版本引用为准。

## 输入与计划

输入只能来自高光服务中已人工审核并带内容哈希的 `ReviewedClipReceipt`，以及本地授权素材库。一个计划的主证据段引用 `HighlightV1` 在原录屏里的绝对时间码；绑定片段时用对应审核收据换算到切片文件的相对入点，并再次校验文件哈希。B-roll 附在主证据段上，是可选的视觉覆盖，不替换该段原声。素材 ID、类型、时间码、授权证据及使用目的写入计划；在匹配、生成时间线和渲染前都用同一平台/地区/商业用途上下文核验授权与文件哈希。

新计划必须明确目标受众、中心问题、开场主张、结尾信息、逐段叙事作用、画面选择和字幕/原声策略。模型只提出候选；服务端校验引用、时间码、最低信息量及三版之间的结构重复。相同镜头顺序加封面、BGM 或仅随机换序的候选标为重复并退回重写。词面与镜头的自动差异只能触发复核，不能证明独立表达或任何平台的“原创”认定；三版始终等待人工审片。

## 时间线与渲染

每版在同一用户项目内保留独立 `project.json`，沿用 Lingji 的编辑器和 Remotion 渲染。主高光切片同时放入视频轨和音频轨；视频用 `videoData.trimStartMs`、音频用 `audioData.trimStartMs` 精确对应审核后的源片段。B-roll 视频或图片覆盖在更高视觉轨，主段音频连续；开场主张与结尾信息可编辑为文字图层。生成前先写计划和来源清单，再原子地落工程文件；渲染输出与哈希、时间线引用、失败原因另存，单版失败不覆盖成功版本。批量任务有固定并发上限、取消和重启核对，不能对不确定输出盲目重渲染。

## 验收

先用合成录屏和授权测试素材验证：三份计划字段完整；高光收据/素材哈希或授权异常均阻断；非零源时间码的画面与原声对齐；三份子工程可分别重开编辑并导出；故意重复的两类对照会触发复核。随后按 `docs/media-evaluation-protocol.md` 用真实已授权样本做文本、源镜头、视觉和音频相似度复核及双人盲审。没有真实样本与平台反馈时，只记录离线结果，不标记 R4 或平台原创验收通过。
