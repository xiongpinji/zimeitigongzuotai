# P0-1 Windows 发行与视频导出复测（2026-09-25）

本记录补充[首次 Windows 基线](p0-1-windows.md)。目标是修复首次出现的“打包进程退出 0、但没有发行产物”以及 480p Remotion 导出失败。验证机为 Windows x64；构建使用独立的 Node `v22.23.3` 与 NSIS 3.12。未使用真实平台账号、付费模型或用户素材。

## 已验证

| 项目 | 结果与证据 | 边界 |
| --- | --- | --- |
| Electron 二进制安装检查 | `ensure-electron-binary.cjs` 在安装脚本返回成功后再次检查实际二进制；缺失时定向测试要求显式失败。 | 不把下载脚本退出码当作已安装。 |
| Windows 打包流程 | `package-windows.cjs` 检查便携程序、`app.asar` 和安装包实际存在且非空；Node 提前 `beforeExit` 时置失败退出码。NSIS 使用 UTF-8 输入，并在编译期间把发行目录映射为短盘符以规避深目录扫描。 | 完整发行产物验收见下节。 |
| 类型检查与定向回归 | `tsc --noEmit` 退出 0；`vitest` 覆盖打包、安装器、工程保存和 Remotion 尺寸/编码路径，7 个文件共 56/56 通过。 | 上游完整测试集仍有[已记录的 Windows 基线失败](p0-1-windows.md)。 |
| 源码 Electron 真实导出 | 在隔离数据目录通过实际 `renderVideo` IPC 导出三个 1 秒合成时间线；`ffprobe` 核对横屏 480p 为 H.264 `854×480`，竖屏 480p 为 `480×854`，横屏 720p 为 `1280×720`，MP4 均非空，页面错误列表为空；两种 480p 文件可被 FFmpeg 完整解码。 | 这验证基础编码与尺寸；未覆盖真实录屏素材、字幕、封面或长视频质量。 |
| 便携版实际导出 | 新发行目录 `release/灵机剪影-win32-x64/` 已生成；直接启动其中的 `灵机剪影.exe`，以独立用户数据目录通过同一 `renderVideo` IPC 输出 16,980 字节 MP4。`ffprobe` 为 H.264 `854×480` + AAC；FFmpeg 完整解码退出 0，页面错误列表为空。 | 只完成 1 秒合成时间线的打包后烟测；不是安装器安装验收或真实素材质量验收。 |
| 工程编辑与保存 | 首次基线复测已证明新建工程、进入编辑台、Windows `EPERM` 后重试保存并显示“已保存”，定向测试 20/20 通过。 | 尚未完成真实素材的完整时间线编辑与重开对比。 |

480p 的修复保留时间线原尺寸进行 React 排版，先由 Remotion 截取偶数整数栅格，再在同一次 FFmpeg 编码中缩到精确目标尺寸。需后段缩放时关闭并行预编码，避免 `-c:v copy` 与 `-vf` 冲突。源码导出烟测只用于验证这个故障路径，不代表用户视频成品质量。

## 发行产物与安装验收

Windows 发行命令退出码 **0**。安装包为忽略的本地产物 `app/release/灵机剪影-1.3.1-x64-setup.exe`，大小 **268,619,604 字节**，SHA-256：`F29FC72265651B09B8D3103E9E4DA425E3E9E7D56B3B793FBBD4377DD9765E02`。便携目录内 `灵机剪影.exe` 为 222,754,304 字节，`resources/app.asar` 为 455,978,997 字节，均经非空检查。安装包 `Get-AuthenticodeSignature` 状态为 `NotSigned`。

安装器运行、管理员权限下的安装和卸载尚未执行；当前证明“安装包可构建且便携版可启动、可导出”，**不能宣称安装成功**。首次基线的完整测试失败也尚未清零；P0-1 完整验收仍需安装/卸载与真实素材编辑复测。
