# P2-2 / H1-S2b2b：多录屏高光有界调度核心

`HighlightBatchScheduler` 在已持久化的 `HighlightBatchQueue` 上显式领取本次调用开始时处于 `queued` 的任务，最多同时执行 4 条录屏任务，单条失败不阻断其他任务。重叠的 `runQueued()` 调用以固定 `scheduler_busy` 拒绝，防止同一调度器绕过并发上限。失败只按固定码落盘；`failed` 不自动重试，调用方必须先用队列 `retry()`，每条录屏最多 5 次尝试。取消先持久化 `cancelled`，随后对正在执行的 runner 发出 `AbortSignal`；取消后返回或拒绝的迟到结果都不能改写任务终态。

runner 由调用方注入，本模块没有默认 HotClip 可执行文件、媒体读取、下载、登录、上传、商品挂载或 UI/IPC 入口。runner 返回的上游候选 ID 可能是敏感原文，调度器先按任务 ID 和上游 ID 生成稳定的 `hcand_<sha256>` 不透明标识，再交给队列落盘；高光 ID 必须符合 `hlcv1-<sha256>`，候选与高光数量相同且每项最多 12 条。结果对象、数组及索引只接受自有数据属性，拒绝访问器、自定义迭代器、过长 ID 和额外字段。子进程错误仅映射固定码，未知异常映射 `internal_error`，原始异常消息和 stderr 不进入任务存储。

## 本机证据

测试仅使用合成录屏引用、假 runner 和临时目录。一个取消集成用例调用现有 sidecar 执行临时目录中的合成 Node 子进程，确认调度器 `cancel()` 传递的信号导致该进程退出；不执行真实 HotClip、不打开真实录屏。

| 检查 | 结果 |
| --- | --- |
| 初始 RED | 新建调度器测试时，模块不存在，Vitest 无法装载测试文件。加入调度器后，隐私用例发现合法字符的上游候选 ID 原文会被队列接收并落盘。 |
| 去原文化 RED→GREEN | 用例要求候选 ID 变成稳定不透明哈希；初跑 1 failed、5 passed。加入只读取自有数据索引、任务域哈希后 6/6 通过。畸形 runner 结果、未知异常原文、独立存储同输入稳定 ID 均有聚焦断言。 |
| 候选/高光对应 RED→GREEN | 新用例证明一个候选配零高光会错误进入 `completed`；初跑 1 failed、9 passed。要求两个 ID 列表等长后 10/10 通过。 |
| 取消到子进程 | 合成子进程先报告 PID，再从调度器取消，sidecar 收到 `AbortSignal` 后退出，任务保持 `cancelled`；单项 Windows 聚焦通过。 |
| 最终聚焦与相关回归 | 新调度器 **11/11** 通过；主库 Windows 合跑调度器、队列、投影、sidecar 为 **108 passed、1 skipped**（共 109 项）；`tsc --noEmit --project app/tsconfig.json` 与 `electron-vite build` 均退出码 0。唯一 skipped 仍是本机 symlink 建链权限用例，不计为通过。 |

Codex 核对了调度器、测试和本文三文件的精确 diff，未发现开放 P0/P1。前段状态转移的 GLM 增量复审两次触及 CLI 会话轮数上限，本段没有另起 GLM 模型审查；这里的结论是协调者审查和本机离线测试，不是独立模型终验或真实录屏验收。

## 尚未达到的产品门槛

此处 `completed` 只表示**runner 返回的 ID 已在队列提交**。目前没有把真实 sidecar 候选正文、投影后的 `HighlightV1`、不透明候选 ID 映射以及人工审核记录持久化到生产文档；runner 提供的高光哈希形态也不等于已校验其与录屏时间码和来源哈希一致。因此本模块不能单独供编辑台展示片段、宣称高光成片已生成，或驱动自动发布。H1-S2c 须补候选产物原子提交与四个持久点恢复，再接 H1-S3 的授权真实录屏/HotClip 盲审。进程异常强杀时子进程树能否随主进程退出仍未保证；单实例产品写者与真实平台结果另行验收。
