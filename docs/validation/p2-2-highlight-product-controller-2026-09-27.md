# H1 授权录屏批量导入与显式高光执行控制器（2026-09-27）

接续[产品启动写者与恢复门禁](p2-2-highlight-product-bootstrap-2026-09-27.md)，本次把执行控制器保留在持锁 Electron 主进程内。它能对用户明确指定的本地目录批量导入 1–100 个 MP4/MOV/WebM/M4V 录屏：先逐个验证目录边界和普通文件、计算 SHA-256，全部通过后才一次性写入持久队列。同一路径同一内容重复导入复用既有任务；内容变化生成新任务。队列只存路径引用、摘要和元数据，不存视频字节；启动侧车前仍会重算来源摘要，防止导入后文件被更换。

执行只能通过 `ProductHighlightController.runQueued` 显式触发：调用方需提供绝对可执行文件路径、工作目录、模型端点/名称、时限、并发和尝试上限，并显式允许 HotClip 可能进行的模型下载。调用方提供的 API Key 仅随本次受控子进程环境传入，不写入队列、候选产物或日志。HotClip 仍是另行安装的 AGPL 组件，本仓库没有导入其源码或制作安装包。本轮不自动调度任务、不自动重试失败任务、不执行商品或平台发布。

退出时先停止新派发并取消在途子进程，待其结束后才关闭写者。仍处于 `running` 的任务保留在磁盘上，由下一次持锁启动按有效候选回执补记完成，或标记为 `interrupted` 等待人工重试；这样避免在“产物刚落盘、队列尚未完成”时错误地把任务永久写成取消/失败。零候选也保留为有效的低高光负样本，不伪造候选。

端到端测试使用 OS 临时目录内的合成视频字节和假 Node 子进程，验证两条录屏入队、候选产物、来源变化拦截、零候选、退出时终止进程及重启恢复；**没有调用真实 HotClip、模型、云端接口、账号或平台**。完整测试和源码构建日志保存在被 Git 忽略的 `data/runtime/validation/`；首窗检查使用独立的 `highlight-controller-source-smoke-profile`。本地 HotClip `node --import tsx src/cli/index.ts --help` 返回帮助文本与退出码 1，只说明该 CLI 入口可加载，不证明 `highlights` 推理可用。

当前控制器尚未注册用户可调用的 IPC/界面；未导入 SRT 字幕，已有非空 `transcriptRef` 的任务在该控制器内固定拒绝执行，防止未经核对的字幕路径进入侧车。接下来需完成系统文件选择与授权、IPC/页面、字幕不可变来源回执、真实录屏双人盲审、时间线回写与批量导出。外部 GLM 本轮没有产生独立审查结论；本记录只记 Codex 复查和本地测试证据。整个阶段 R1–R6 仍按原验收矩阵逐项关闭。
