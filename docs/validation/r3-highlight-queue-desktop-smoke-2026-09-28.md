# R3 高光工作台队列离线桌面测试（2026-09-28）

按“先测试、不打包”要求，在 Windows 源码构建 `7cfbfc7` 上运行 `node app/scripts/smoke-highlight-queue-win.cjs`，退出码 0。脚本在 Git 忽略目录内生成两段各 4 秒的纯色 MP4，使用独立 Electron `userData` 与空工程；测试驱动只代替系统文件对话框提供这些合成路径，导入、取消等操作经真实高光页按钮与生产 IPC 执行。

两段视频导入后形成不同来源 SHA-256 的排队任务。经界面取消其中一条并关闭应用，重启后取消与排队状态及任务 ID 均保持不变。再次选择相同文件导入，任务数仍为 2；随后把同路径第一段视频改为不同内容再导入，新增第 3 个任务和新的来源摘要，旧任务仍在。页面异常 0。未配置 Node/HotClip/模型时“运行排队任务”按钮禁用；直接用 IPC 提交缺少模型下载许可的请求，得到 `consent_required`，没有进入分析进程。结果、队列文件与前后截图在被 Git 忽略的 `data/runtime/validation/r3-highlight-ui-1790548314628/`。

同一业务源码的高光工作台、产品 IPC、控制器、授权录屏导入和启动组合根聚焦测试 **5/5 文件、27/27 通过**。这轮只验证批量导入、来源身份、去重、取消和重启恢复的桌面路径；没有启动 HotClip、ASR 或 LLM，也没有高光候选、切片导出或质量评审。因此 [R3 产品验收](../roadmap-and-acceptance.md)仍未关闭，尤其不能把两段纯色视频当作直播高光质量样本。
