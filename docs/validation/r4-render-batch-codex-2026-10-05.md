# R4 B1 多版本批量渲染：源码与离线验证（2026-10-05）

基线 `276bda2`；用户要求先测试、不打包。本轮只做多版本工程的主进程批量渲染服务、Remotion 取消端口、离线合成样本验证。没有 IPC、产品按钮、平台账号、真实录屏、在线模型或发布动作。外部 GLM 只读审查未通过，后续 R4 产品入口及真实授权素材审片仍是独立关口。

## 行为

- `app/electron/composition/render-batch.ts` 从已保存的版本工程和来源清单读取输入，不接收外部输出路径或外部声称的核验结果。每次复用完成文件前、以及排队后真正开始编码前，都重新调用来源/授权核验；除核验时间外，身份、时间码、哈希、平台/地区/商业用途须与版本清单一致。手工改过的时间线要求重新审核。
- 全进程批量渲染最多两路；同一批次有单一所有者。每版独立的 `render-state.json` 原子写入并 `fsync`，先写唯一临时 MP4、校验普通文件和哈希，再用独占硬链接提交派生输出。失败不影响其他版本；已完成文件在复用时重新核验来源和输出哈希；确认失败要显式 `retryFailed` 才重试。中断时遗留的 `rendering` 转为 `unknown`，不自动重渲染。
- 取消先阻止排队任务、向活跃任务传递 `AbortSignal`，等待活跃 Promise 真正结束后才释放两路槽位。`render-video-headless.ts` 给批量调用提供 1–4 的帧并发上限、阶段取消检查和打包态 cwd/清理串行门槛；旧单片导出不传新参数时沿用原默认配置。`render.ts` 将取消接入 Remotion `makeCancelSignal`/`renderMedia`，合成选择阶段结束后再检查取消。
- 返回结果保留 `reviewRequired: true`，不声称质量复核、原创性或平台判定通过。错误码固定，不把原始异常和批量临时输出路径传到安全结果或批量开发日志。

## 未解除的关口

此证据支持 R4 B1 的本地源码与合成渲染，不代表 R4 产品交付。B2–B4 的产品调用、用户可见状态和审片入口仍未接线；安装包、跨进程并发、真实授权录屏、真实素材授权撤销、长期稳定性、真实平台原创判定和外部 GLM 只读审查未验。Windows 当前权限不允许创建文件 symlink 测试夹具（`EPERM`）；源码用 `lstat` 拒绝 symlink，损坏状态的实际测试已通过，symlink 场景尚需在可创建链接的隔离环境复核。两路是本地上限，不是极限发布吞吐证明。
