# R5 智能体质检活动授权：源码与隔离桌面验证（2026-10-05）

本轮把独立生产 MCP 的“账号 × 已审核视频只读预检”接入受信任活动授权。用户在当前工程的设置页点击“授权 30 分钟”，主进程弹出原生确认框；确认后授权按工程、动作和有效期写入 `userData/production-v1/activities.json`。文件只保存工程路径的 SHA-256 标识、`quality_check` 动作和安全审计码，不保存工程路径、账号会话或素材。撤销和到期后，每次工具调用重新读取存储并拒绝。授权范围明确排除登录、草稿写入、排队发布和平台提交。

测试先以缺少活动存储模块的失败用例起步，再实现存储与 IPC 接线。聚焦 5 个测试文件共 47 项通过：默认拒绝、跨工程、持久化、撤销、到期、损坏文件、外来窗口、确认取消、确认期间工程切换、MCP 工具动态拒绝与允许。全量 411 个测试文件通过，3036 项通过、4 项跳过；其后新增设置页入口测试 1 项并单独通过。工程切换触发设置页状态刷新后，聚焦 4 文件 5 项、`npx tsc --noEmit` 和 `npx electron-vite build` 均退出 0。隔离 `node scripts/smoke-production-mcp-win.cjs` 再次退出 0：专用令牌认证与两项生产只读工具可用；无授权返回 `grant_missing`，模拟用户确认后预检进入账号检查并返回 `account_missing`，撤销后恢复 `grant_missing`；旧 31 项工具保持。最终结果保存在 Git 忽略的 `data/runtime/validation/r5-mcp-1791168880493/`。

隔离桌面探针在专用测试进程里用模拟的原生确认响应完成 IPC → 持久授权 → MCP 预检 → 撤销闭环；没有实际点击系统确认框或设置页，真实 UI 操作还需单独验收。当前证据只证明本地源码/合成桌面路径，不证明真实素材质检质量、四平台账号保持、商品挂载或发布最终状态。R5 九类动作中只有质检预检的受控读取接线，自动生产、可恢复审计与自动发布仍未完成。本轮未打包、未登录真号、未调用付费模型、未发布。
