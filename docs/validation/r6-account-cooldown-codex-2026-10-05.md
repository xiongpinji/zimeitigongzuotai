# R6 发布队列账号冷却源码验证（2026-10-05）

在[原严格探针](r6-account-cooldown-readiness-2026-09-28.md)基础上复测，修复前四平台标识的同账号停派 0/8 通过，未知提交对照 4/4 通过。用户已[授权 Codex 接手阶段一剩余源码](../decisions/2026-10-05-codex-source-takeover.md)；本子项只改通用持久队列、相应用例和验证记录，不接真实平台。

队列现在把已确认未提交的 `throttled` 结果记录为任务上的 `throttleUntil` 与 `throttleScope`，每轮领取前从所有任务推导账号/平台停派范围。未显式给范围时保守按该账号停派；执行器可明确给 `task` 或 `platform`，不从错误文案猜范围。原任务即使被手动提前重试或取消，其冷却记录仍保持到时间届满；未知提交继续先核对、不盲重发。同平台其他账号在账号范围限流期间可继续执行。旧 v1 文件无这两个字段时按空冷却读取；字段损坏则拒绝加载且不改原文件。

测试先行：新增账号范围用例在旧源码下失败，重新打开后第二次提交了原任务；平台/任务范围用例也因不识别范围失败。实现后又发现 `retryNow` 可绕过任务范围的等待，补 RED 用例后加入领取守卫。最终 `app/tests/publish/durable-queue.test.ts` 46/46 通过；队列、适配器、产品 bootstrap 与属主相关四文件的聚焦测试在加入旧文件兼容用例前为 92/92，通过后单文件 46/46。完整回归包含最终源码。

严格探针 `node app/scripts/probe-publish-account-cooldown.cjs` 在最终源码上退出 0，12/12 场景通过，证据位于被忽略的 `data/runtime/validation/r6-account-cooldown-KxAMlD/result.json`；四个平台标识各覆盖当前对象与重新打开后的账号冷却，另各有未知提交对照。Windows 双进程崩溃用例通过。使用专用 `vitest.load.config.ts` 的三项千任务测试均通过：100 账号/1000 任务/8 worker 正常推进、1000 个未知提交核对、8 条进程中断租约恢复；这些负载测试开始于最后一条 `retryNow` 守卫加入之前，守卫由后续聚焦和完整回归覆盖。最终源码的全量 `npx vitest run --maxWorkers=2 --minWorkers=2` 为 394 文件通过、2978 项通过、4 项跳过、0 失败。`npx tsc --noEmit` 与 `npx electron-vite build` 在最终源码上均退出 0，后者仅为源码构建，无安装包。

该证据只证明注入合成执行器的队列调度；真实平台适配器尚未返回限流范围，也未通过真实账号发布、平台最终状态或高并发吞吐验收。商品请求仍在原有 fail-closed 门槛内。GLM 针对当前源码的只读复审尚未取得，不用本报告代替 R6-P 整体验收。
