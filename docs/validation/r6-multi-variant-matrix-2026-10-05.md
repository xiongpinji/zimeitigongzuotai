# R6 多视频版本发布矩阵：离线源码验证（2026-10-05）

基线 `045d4fc`。阶段一要求每个目标账号可选择具体视频版本，而原有 `enqueueMatrix` 只能把同一版本展开到多个账号。当前继续按用户要求测试源码，不打包、不登录真实账号、不触发平台发布。

新增 `enqueueMatrices`：一次接收多组“视频版本 × 账号”，先完整校验所有组、检查批次内重复键和已有任务的幂等指纹，再以一次持久化写入创建所有新任务。原 `enqueueMatrix` 沿用同一实现。批次中已有任务保持原状；任何后续组输入错误、同键载荷冲突或写盘失败，不能留下部分新任务。商品请求仍必须显式传 `null` 或完整对象，普通发布不会从缺失字段暗中降级。

新增两组用例修复前因缺少整批 API 而失败。最终队列核心 **54/54** 通过，覆盖每账号不同版本、整批幂等、无效后项、已有任务冲突、批次重复键、已有与新任务混合以及写盘失败后的内存快照。发布相关回归 **27 个文件、372 项通过、1 项既有跳过**；`npx tsc --noEmit` 和 `npx electron-vite build` 均退出 0。未重跑默认全量套件或千任务负载；这次改动只涉及队列入队 API 与对应测试。

此项是产品接线所需的原子队列能力，**不是**发布工作台已能选择安全账号和可信渲染版本的证据。当前产品队列仍使用惰性执行器；还需主进程核对渲染哈希、来源许可、人工复核和账号会话，提供受控的预检/入队入口，之后再接真实平台适配器与远端最终状态核对。R6-P 和阶段一整体继续未完成。
